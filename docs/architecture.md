# Architecture

The Zotero extension owns the reader UI and local PDF context. The hosted Cloudflare Worker owns explicitly published marks, replies, and AI guides in D1. The loopback Node service is an optional local Codex bridge and legacy two-reader prototype. It is never a public backend. Zotero item records and personal annotations are not modified by remote rendering.

## Data flow

1. The extension computes a SHA-256 digest of the local PDF. Anonymous readers only query the Worker for that digest; the PDF metadata is registered when an authenticated user publishes. No PDF bytes or local path are sent. An exact digest is the pilot matching key; it does not equate different PDF editions.
2. Anonymous reads retrieve public highlights and notes. Writers use a distinct invited-user token. The Worker hashes the credential and resolves the author from its `users` table; it ignores client-supplied owner and author fields. The extension draws transient overlays only on rendered pages. Public highlights and notes have independent visibility switches.
3. The AI guide panel defaults to a detailed beginner tier; standard and concise tiers have separate cache keys. Opening a guide requests the already-published result first. Only a cache miss lets the reader invoke the local Codex bridge. The bridge reads a PDF from Zotero storage, extracts bounded text with `pdftotext`, asks Codex for an overview and anchored comments, and checks that quotations appear on the stated page. Beginner generation requires a step on each selected content page (up to 18), skips bibliography-only pages, and makes one targeted repair attempt for gaps. Results remain a private preview under the Zotero data directory's `social-reading/guides` folder until the reader clicks to publish. The reader panel advances step by step and seeks the quoted text in the PDF.
4. Publishing uploads only the guide text, quoted excerpts, PDF page indices, tier, and prompt version. The Worker uses a unique `(document, tier, prompt_version)` key so readers reuse one guide per exact PDF and tier. Beginner version 2 is separate from the earlier, shorter version 1; standard and concise remain version 1. Older clients continue to request version 1 by default. The client locates quotations in its local PDF text layer and displays them inline. AI labels remain visible.
5. Public comment/reply bodies and AI guide notes remain source text in storage. The reader renders them through a bundled Markdown parser and KaTeX with raw HTML escaped, restricted link opening, and KaTeX trust disabled. This is local display behavior; no D1 migration is required.
6. The optional Codex sidebar handoff uses `Zotero.CodexSidebar` contract version 1 with primitive arguments `(attachmentID, prompt, tabID)`. The receiving sidebar checks the open PDF and tab, initializes its paper pane if needed, and appends an editable prompt. Only the reader's explicit Send action starts a Codex turn; only Social Reading's explicit Publish action writes to the shared service.

## Boundaries and limitations

The optional local service binds only to `127.0.0.1`, uses a private installation token, and only accepts PDFs under Zotero storage. The hosted Worker is invite-only for writes, but reads are public. It currently has no self-registration, spam limits, moderation interface, or per-edition text anchoring. A guide quote is checked against local extracted text before generation returns; the Worker cannot independently verify the PDF. Concurrent first-time readers may both spend local tokens, but only one guide wins publication. Reader overlays use Zotero internals and require visual regression testing after Zotero updates. The local AI bridge requires Node 24, Poppler, a logged-in Codex CLI, and working network access.
